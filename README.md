# პროექტის ზოგადი აღწერა: Food-101 სურათების კლასიფიკატორი:

პროექტი წარმოადგენს საკვები სურატების კლასიფიკატორ მოდელს, რომლის ფარგლებშიც მოდელები გაწვრთნილია 101 სხვადასხვა კატეგორიის კერძის სურათებზე. პროექტში წარმოდგენილია E2E სახით, რომელიც მოიცავს: მონაცემთა მიღებას, დამუშვებას, სხვადასხვა კატეგორიის მოდელის გაწვრთნას, ექსპერიმენტების ავტომატურ აღრიცხვას (zenml პლატოფრმის მეშვეობით), შეფასებას და ინტერაქტიულ აპლიკაციას (რომელიც პროექტის ფარგლებში გავრთნილი საუკეთესო მოდელის გატესტვის საშუალებას იძლევა). სისტემის ტერმინალიდან სამართავად სამართავად გამოყენებულია click ფუნქციები.


## გამოყენებული მონაცემთა ნაკრები

პროექტი იყენებს **Food-101** მონაცემთა ნაკრებს (`from torchvision.datasets import Food101`), რომელიც მოიცავს 101 კერძის კლასს, თითოეულ კლასში წარმოდგენილია 1000 სურათი, ჯამში 101,000 სურათი (პროექტის ფარგლებში მონაცემთა მიღების მომენტში ხდება თითოეული კლასიდან რენდომ პრინციპით მონაცემტა 50%-ის ამოშლა, რათა ტრეინინგის დრო დასწრაფდეს, ცხადია მოდელის სიზუსტეზე უარყოფითად აისახება თუმცა მთავარი მოდელის დემოსტრირებაა და არა საუკეთესო მაჩვენებლების ჩვენება). საწყის მონაცემთა ნაკრებში თითო კლასზე 350 სურათი train ნაწილისთვისაა, 50 valid ნაწილისთვის, ხოლო 100 — test ნაწილისთვის. მონაცემებში დასაშვებია გარკვეული უზუსტობების არსებობა (არსებობს არასწორად კლასიფიცირებული მონაცემები) (https://docs.pytorch.org/vision/main/generated/torchvision.datasets.Food101.html).

### მონაცემთა სტრუქტურა

`ImageFolder` თითოეულ ქვესაქაღალდეს ცალკე კლასად აღიქვამს და საქაღალდის სახელს კლასის დასახელებად იყენებს. სურათები `ingest()` ფუნქციაში `224×224` ზომაზე გადაიყვანება რომელიც მონაცემტა ნაკრებად Tensor ფორმატში ბრუნდება.


### საწყისი მონაცემების დაყოფა და პროექტის დაყოფა

 პროექტში `ImageFolder` ყველა სურათს ერთ dataset-ად კითხულობს. შემდეგ `batch_tranform()` ამ ერთიან dataset-ზე `random_split()`-ს იყენებს, რათა მონაცემთა გაყოფა რენდომ პრინციპით მოხდეს (არ ხდება სტრატიფიკაცია, რომელიც თითოეული კლასიდან ტანამაბარი რაოდენობის მონაცემთა აღებას შეძლებდა, თუმცა სხვადასხვა მოდელების შედარებისას თანაბარი მონაცმეთა კლასის ნაკრების აღებისთვის გამოყენებულია `generator = Generator().manual_seed(seed)`). Validation და test `DataLoader`-ებში `drop_last=True`-ია, ამიტომ ბოლო არასრული batch-ები შეფასებაში არ შედის.

`data_size` პარამეტრი სრული dataset-ის რა წილი გამოიყენოს, მთლიანი pipeline-ის სწრაფი ტესტირებისთვის არის მხოლოდ გამოყენებული, მონაცემტა ზომად მცირე რიცხვის მიტითება ხდებოდა რათა სრული ჯაჭვის გამართულად ფუნქციონირებაში დავრწმუნებულიყავი.


### თითო კლასში სურათების განახევრების კომენტირებული კოდი

`src/ingestion_functions.py`-ში, `data_downloader()`-ის შიგნით, კოდი კომენტარის ველითაა დატოვებული და არ სრულდება. მისი ჩართვისას `APPLY=True` იქნება აუცილებელი მიეთითოს.



## Pipe: 1 გაწვრთნა-შეფასების pipeline (`run_training_eval_pipe`)

ფაილი: `pipeline/train_eval_test_pipe.py`.

ეს pipeline წინა ნაბიჯებს ამ თანმიმდევრობით აერთებს: `ingestion_func` ქმნის train/validation/test loader-ებს, `training_fuction` train და validation მონაცემებზე წვრთნის მოდელს, ხოლო `eval_function` სატესტო ნაკრებზე აფასებს. Pipeline-ის დაბრუნებული მნიშვნელობა საბოლოო test accuracy-ა.


### ნაბიჯი 1: მონაცემების მიღება და დაყოფა (`ingestion_func`)

>>ფაილი `steps/ingestion_step.py`, და მისი მთავარი ფუნქცია სახელად:`ingestion_func`. 

>>დანინშულება: მონაცემთა დამუშავება, გარდაქმნა, ტრენინგის, ტესტირების, ვალიდაციის ნაწილებად დაყოფა და გადაცემა.

1. **`data_downloader(raw_data_store_path, download=False)`**- მინაცემტა გადმოწერა. 
2. **`ingest(data_folder_path, shape_size)`**- ქმნის torchvision-ის `ImageFolder` dataset-ს. საქაღალდის ყოველი ქვესაქაღალდე ერთ კლასს წარმოადგენს, ხოლო ქვესაქაღალდის სახელი კლასის დასახელებას.
3. **`batch_tranform(dataset, data_size, batch_size, train_size, val_size)`**- ირჩევს dataset-ის პირველ `data_size` წილს, შემდეგ `random_split`-ით ყოფს train, validation და test ნაკრებებად.
4. **OpenVINO-ს მაგალითის შენახვა** — `batch_tranform` test loader-იდან პირველ batch-ს იღებს და პირველი სურათის Tensor-ს `data/openvino_example_input.npy` ფაილში ინახავს. ეს მაგალითი მოგვიანებით PyTorch მოდელის OpenVINO ფორმატში გადასაყვანად გამოიყენება (ინფერენს ნაწილში).



### ნაბიჯი 2: გაწვრთნა (`training_fuction`)

ფაილი: `steps/training_step.py`; მოდელები და დამხმარე ფუნქციები: `src/models_architecture.py` და `src/params.py`.

`training_fuction` მუშაობს ZenML-ის ნაბიჯად, ჩართული აქვს `experiment_tracker=True` და დროის აღრიცხვის დეკორატორი `@time_it`.

1. MLflow-ში პარამეტრებად წერს არქიტექტურას, მოწყობილობას, ოპტიმიზატორს, learning rate-ს, epoch-ების რაოდენობას, dropout-ს, კლასების რაოდენობას, `freeze`-სა და `pretrained`-ის მნიშვნელობებს.
2. `load_model_for(model_name)`-ით ირჩევს მოდელის კლასს:
   - **`MobileNetClassifier`**- torchvision-ის MobileNetV3-Large; საბოლოო classifier იცვლება 101 კლასზე.
   - **`EfficientNetClassifier`**- torchvision-ის EfficientNetV2-S; საბოლოო classifier იცვლება 101 კლასზე.
   - **`CustomCNN`**- პროექტში შექმნილი CNN მარტივი მოდელი, რომელიც convolution, ReLU, max-pooling და fully connected ფენებს იყენებს.
3. pretrained მოდელებში `freeze=True`-ისას feature ფენების წონები იყენებს. `custom` მოდელს pretrained წონები არ აქვს.
4. `loss_function("cross_entropy_normal", loss_label_smoothing)`-ით ქმნის Cross Entropy loss ფუნქციას.
5. `optim_function(optim_name, learning_rate, trainable_parameters)`-ით Adam ან AdamW optimizer-ს ქმნის. ამათგან გამოყენებულია მხოლოდ მეორე კატეგორიის ოპტიმაიზერი (როგორც მიმოვიკვლიე, იგი უფორ ზუსტი და დასრულებული ოპტიმიზაციის განტოლებაა).
6. `metrics("acc", num_class)`-ით TorchMetrics-ის multiclass სიზუსტის ფუნქცია..
7. ყოველ epoch-ზე MLflow-ში წერს `train_loss`, `train_accuracy`, `val_loss` და `val_accuracy` მეტრიკებს. ფუნქცია ბოლოს CPU-ზე აბრუნებს გაწვრთნილ მოდელს და მოდელის სახელს.

`@time_it` გაწვრთნის ფუნქციის შესრულების დროს ზომავს და კონსოლში ბეჭდავს. `src/params.py`-ის `metrics`, `loss_function` და `optim_function` მოდელის შესაბამის დამხმარე ობიექტებს ქმნიან.

>>შენიშვნა: გაწვრთნის ეტაპზე შესაძლებელია Intel GPU-ის გამოყენება (xpu მოწყობილობა), რომელიც ჩემს მოწყობილობას გააჩნია და Intel CPU-სთან სედარებიტ 5 ჯერ სწრაფად ასრულებდა ფუნქციებს. default mode-ად CPU არის მოცემული რათა მოდელმა სხვა მოწყობილობაზე მუშაობა ცვლილებბეის გარეშე სეძლოს. 

### ნაბიჯი 3 — შეფასება და checkpoint-ის შენახვა (`eval_function`)

ფაილი: `steps/eval_step.py`.

`eval_function` გაწვრთნილ მოდელს სატესტო მონაცემებზე აფასებს მოდელს:

1. არცეული Accyracy-ით ქმნის მოდელის სიზუსტის მონაცემს-ს, ხოლო f1 ფუნქციად აღებულია F1 macro mode, რათა ანგარიშისას კლასთა შორის განსხვავება ანგარიშში არებულიყო.
2. OpenVino test loader-იდან მაგალით batch-ს იღებს და `ov.convert_model(...)`-ით PyTorch მოდელს OpenVINO მოდელად გარდაქმნის.
3. `ov.compile_model(..., device_name=infer_proc_unit)`-ით მოდელს არჩეულ მოწყობილობაზე: CPU, GPU ან NPU, შესრულებისთვის ამზადებს.
4. სატესტო batch-ებს OpenVINO მოდელში ატარებს და აგროვებს საშუალო test loss-ს, accuracy-სა და macro F1-ს.
5. შედეგში ინახავს PyTorch state dict-ს `saved_models/<model_name>/` საქაღალდეში. ფაილის სახელში test accuracy შედის, მაგალითად: `<model>_<თარიღი>_acc_0.7727.pth`.
6. აბრუნებს `avg_test_loss`, `final_acc` და `final_f1` მნიშვნელობებს. ეს მნიშვნელობები ZenML run-ის step output-ებად ინახება.


## Pipe 2: მოდელის გამოქვეყნების გადაწყვეტილება (`run_deployment_pipe`)

ფაილი: `pipeline/deploy_pipe.py`; დამხმარე ფუნქციები: `src/depl_functions.py`.

გამოქვეყნების pipeline არჩეული არქიტექტურის ბოლო checkpoint-ს ამოწმებს, თუ accuracy ზღვარს ვერ აღწევს, გამოქვეყნებას წყვეტს და კლასიფიცირებულ მოდელს saved_models ფოლდერში ინახავს. თუ გადალახა, კითხულობს `data/openvino_example_input.npy`-ს, მოდელს OpenVINO ფორმატში გარდაქმნის და `best_model/`-ში წერს `active_model.xml`, `active_model.bin` და `active_classes.json` ფაილებს.


## Pipe 3: სურათის კლასიფიკაცია (`inference_pipe`)

ფაილები: `pipeline/inference_pipe.py`, `steps/inference_step.py` და `src/inference.py`.

`inference_pipe` სურათის Base64 ტექსტსა და მოწყობილობის სახელს `predict_image_step`-ს გადასცემს. `predict_image_step` იძახებს `predict_food_image`-ს, შედეგს კონსოლში ბეჭდავს და ZenML metadata-ში ინახავს არჩეულ მოწყობილობასა და prediction-ს.

`predict_food_image(image_base64, infer_proc_unit)` შემდეგს აკეთებს:

1. Base64 მონაცემს სურათის ბაიტებად შლის, PIL-ით ხსნის და RGB ფორმატში გარდაქმნის.
2. `best_model/active_classes.json`-იდან კლასების სახელებს კითხულობს.
3. `active_model.xml`-ის ფაილის მდებარეობას, შეცვლის დროსა და ზომას იყენებს მოდელის დასადგენად. **`compile_model`** OpenVINO მოდელს არჩეულ მოწყობილობაზე გარდაქმნის; `@lru_cache(maxsize=4)` უკვე დაკომპილირებულ მოდელს ხელახლა გამოყენების საშუალებას აძლევს (რაც გარკვეულ წილად აჩქარებს პროცესებს, აღარ უწევს ყველაფრის ტავიდან ჩატვირთვა).
4. სურათს `224×224` ზომაზე ამცირებს და Tensor-ად გარდაქმნის; შემდეგ OpenVINO მოდელით logits-ს იღებს.
5. logits-ს softmax-ით ალბათობებად გარდაქმნის, ყველაზე მაღალი ალბათობის მქონე ხუთ კლასს პოულობს და აბრუნებს მთავარ კლასსა და `top_5` სიას.





## სამართავი ფუნქცია (`run_deployment.py`)

`run_deployment.py` Click-ზე დაფუძნებული ფუნქციების კრებულია. `--config train-deploy` თანმიმდევრულად უშვებს გაწვრთნისა და შეფასების pipeline-ს. `--config infer` `--image-path`-ით მითითებულ ლოკალურ სურათს პროგონიზრების pipeline-ში გადასცემს. რომელიც ლოკ ჰოსთზე ეშვება. ( ამჟამად Gradio/Hugging Face ვებაპი კი არა)
